## Workload

An operator-level slice of an attention block, batch 1:

```
ln     = layernorm(x)          [S, H]
Q      = ln @ Wq               [S, H] @ [H, H]
K      = ln @ Wk               [S, H] @ [H, H]
V      = ln @ Wv               [S, H] @ [H, H]
Kt     = transpose(K)          [H, S]      <- torch, in BOTH paths
scores = Q @ Kt                [S, H] @ [H, S] -> [S, S]
probs  = softmax(scores)       [S, S]
ctx    = probs @ V             [S, S] @ [S, H]
out    = ctx @ Wo              [S, H] @ [H, H]
out    = layernorm(out)        [S, H]
```

Configurations: S=128,H=768, S=512,H=768, S=1024,H=768, S=128,H=1024, S=512,H=1024, S=1024,H=1024.

Two caveats about the pipeline, stated rather than hidden:

* The `1/sqrt(d)` attention scale is folded into `Wq` before the run, because the library has no elementwise scale kernel. Identical arithmetic, applied once instead of per iteration, for both paths.
* The transpose uses PyTorch in **both** paths, because the library has neither a transpose kernel nor a transposed-operand matmul. It is inside the timed region for both, so it does not bias the comparison, but the custom pipeline is not 100% custom. This is a real gap in the library.

## Correctness

Each operator checked on 3 independent random inputs per configuration, against a float64 PyTorch reference computed from the same float32 inputs.

| Operator | Verdict | Worst scaled relative error |
|---|---|---|
| matmul | **PASS** | 7.377e-06 |
| layernorm | **PASS** | 2.384e-07 |
| softmax | **PASS** | 2.119e-06 |
| pipeline | **PASS** | 1.120e-05 |

Relative error is scaled by the RMS of the reference rather than measured per element: a matrix-product element can cancel to near zero, which makes a per-element relative figure meaningless. See `tests/support/compare.h`.

## Benchmark methodology

* CUDA events recorded in the stream, not a host clock.
* 10 warmup + 30 measured iterations per operator; 5 + 15 for the pipeline.
* Warmup discarded: the first launches pay module load and the clocks are still ramping from idle.
* Both paths are driven from Python and timed identically, so per-launch Python overhead is present in both.
* Reference is PyTorch, which dispatches to cuBLAS for matmul and its own fused kernels for layernorm and softmax.

## Analysis

### Which operator dominates

* **S=128,H=768** — of the custom operator time, matmul (tiled) 68%, layernorm 19%, softmax 13%.
* **S=512,H=768** — of the custom operator time, matmul (tiled) 78%, layernorm 14%, softmax 8%.
* **S=1024,H=768** — of the custom operator time, matmul (tiled) 79%, layernorm 12%, softmax 8%.
* **S=128,H=1024** — of the custom operator time, matmul (tiled) 70%, layernorm 19%, softmax 11%.
* **S=512,H=1024** — of the custom operator time, matmul (tiled) 85%, layernorm 9%, softmax 5%.
* **S=1024,H=1024** — of the custom operator time, matmul (tiled) 87%, layernorm 8%, softmax 5%.

### Where the custom kernels stand

* Worst ratio: **matmul (naive)** at S=1024,H=1024, 0.09x (4.415 ms against 0.408 ms).
* Best ratio: **softmax** at S=128,H=768, 0.52x (0.040 ms against 0.021 ms).

### Scaling with workload size

* **matmul (tiled)**: 0.32x at S=128,H=768 -> 0.12x at S=1024,H=1024.
* **layernorm**: 0.46x at S=128,H=768 -> 0.18x at S=1024,H=1024.
* **softmax**: 0.52x at S=128,H=768 -> 0.30x at S=1024,H=1024.
* **PIPELINE (end-to-end)**: 0.32x at S=128,H=768 -> 0.17x at S=1024,H=1024.

### Primary bottleneck

Summed across every configuration, the operator losing the most absolute time against the reference is **matmul (tiled)** (6.260 ms total deficit). Full per-operator deficits:

* matmul (tiled): +6.260 ms
* layernorm: +0.763 ms
* softmax: +0.406 ms

### Next optimization target

**matmul (tiled).** It carries the largest absolute deficit and, per the share breakdown above, the largest fraction of pipeline time. The naive and tiled matmul rows in the table give the in-library reference point for what a structural change to that kernel is worth.

## What this does not establish

* Nothing about an Ada (sm_89) GPU; this ran on the hardware named above.
* Nothing about batched or multi-head attention; batch is 1 and the pipeline is single-head-shaped.
* Nothing about training; there is no backward pass.
* No claim that any kernel is well optimized. None has been tuned, and block and tile sizes were chosen by reasoning rather than measurement.
