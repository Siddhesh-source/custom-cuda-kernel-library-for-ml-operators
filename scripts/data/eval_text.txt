A graphics processor is built to run thousands of small programs at once. Each program, called a thread, works on its own piece of data, and threads are grouped into warps of thirty-two that issue instructions together. When every thread in a warp follows the same path through the code, the hardware runs them in lockstep; when they disagree, the warp runs each path in turn and the unused threads wait.

Memory is the usual limit. A modern card can perform many more arithmetic operations per second than it can fetch numbers from its main memory, so a program that touches each number only once spends most of its time waiting. Programmers therefore look for reuse: a tile of a matrix is loaded once into a small, fast memory shared by a group of threads, and every thread in the group reads it many times before the next tile arrives.

Normalization layers and softmax are the opposite case. They read a row, compute one or two summary values such as a mean or a maximum, and write the row back. There is almost no reuse, so the best such kernel simply moves bytes as fast as the memory allows. The work is in making sure that nothing else gets in the way: no wasted passes over the data, no slow arithmetic in the inner loop, and enough threads in flight to hide the long wait for each load.

Language models combine both kinds of operation. A single layer multiplies the input by large weight matrices, normalizes the result, and computes attention scores that pass through a softmax. When the model generates text one word at a time, each matrix product involves only a single row of activations, and the operation turns from arithmetic-bound to memory-bound. Fast generation then depends on reading the weights as quickly as possible, which is a different problem from training the same model on long batches.

Measuring any of this honestly takes care. Clocks change with temperature and power, other programs may share the device, and a small kernel can finish before the processor has even submitted the next one. A careful benchmark warms the device up, repeats each measurement many times, reports the median and its spread, and checks every result against a trusted reference before it is allowed to count.
