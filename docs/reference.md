Overview Vendor kernels are tuned for general shapes. If your models use specific hidden sizes, sequence lengths and batch sizes, hand-tuned or fused kernels can win on those shapes. This project builds matmul, layernorm and softmax kernels step by step, profiles each optimization, and benchmarks against cuBLAS and PyTorch. Research question On which target shapes and dtypes can hand-written kernels beat cuBLAS / PyTorch, and which optimizations produce the gain? Expected outcome A kernel library that beats vendor baselines on target shapes by a measurable margin. Prerequisites and hardware Skills: C/C++, basic CUDA (threads, blocks, shared memory), PyTorch basics. Hardware: Any NVIDIA GPU for development. Tensor Core work needs compute capability 7.0+ (BF16 needs 8.0+). Hardware-counter profiling usually needs a local or rented GPU, not a shared notebook. 2. Architecture / pipeline Target-shape list -> reference implementations -> naive kernels -> optimized kernels (one optimization at a time) -> correctness tests -> benchmark harness -> Nsight Compute analysis -> PyTorch extension -> final shape-by-shape comparison table. 3. What to build • Shape list: extract the real (M, N, K), hidden size, sequence length and batch size values from your production models. • Matmul ladder: naive -> shared-memory tiling -> register blocking -> vectorized loads (float4) -> double buffering-> Tensor Cores (WMMA or mma.sync). Record speedup after each step. • Layernorm: one block or warp per row, Welford or two-pass variance, warp-shuffle reductions, vectorized access, optional fusion with residual add or bias. • Softmax: numerically stable (subtract row max), online softmax, warp-per-row for short rows and block-per-row for long rows, optional fused scaling or masking. • Correctness suite: compare to PyTorch float64 reference with explicit tolerances per dtype (FP32, FP16, BF16). • Benchmark harness: warmup, CUDA events, median over many iterations, TFLOPS and GB/s computation, CSV output. • PyTorch extension (torch.utils.cpp_extension) so kernels can be called from Python and dropped into a model. 4.
